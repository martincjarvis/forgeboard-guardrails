# An unmodified plugin copy still counts toward change size

## Decision

**No change. A file copied byte-identical from the plugin's own scripts counts
toward change size the same as any other tooling file.**
[ADR-0005](0005-generated-files-discounted-from-change-size.md)'s
`guardrail-generated` discount does not reach it. The position is the one
[slice 1](../specs/2026-08-01-distributable-guardrails-slice-1-foundations.md#change-size)
already states — "nothing here is exempted from change-size counting, and no
new exemption is proposed" — and the one
[ADR-0008](0008-tooling-complexity-band.md) already affirmed: the bootstrap
commit's override row is the mechanism that handles the size, not a discount
on the copied bytes.

## Why this is a record rather than a non-decision

The argument for discounting is almost word-for-word
[ADR-0005](0005-generated-files-discounted-from-change-size.md)'s: nobody
wrote these bytes, so there is nothing in them for a reviewer to review.
ADR-0005 states it for generated files; a copied file makes the same claim,
and the claim is genuinely adjacent rather than a strawman. This record
exists because a future reader who reopens the question without it
reconstructs the same case from scratch instead of arguing against the
recorded answer.

[ADR-0008](0008-tooling-complexity-band.md) already rejected the nearest
version of this — "ported gate scripts are copied, not generated; a human
can act on them, edit them, simplify them" — and the reasoning there is the
one this record carries forward: **a copy can be edited where a generated
file cannot.** That distinction is load-bearing for everything below.

## Rejected alternatives

- **Discount copied bytes as generated.** Apply
  [ADR-0005](0005-generated-files-discounted-from-change-size.md)'s discount
  to any file the bootstrap copied byte-identical, on the same grounds: no
  author wrote them, so there is nothing to review. Rejected on ADR-0008's
  grounds. A generated file is regenerated by a tool on every run, and any
  local edit is discarded the next time the tool runs — that is what makes
  "no author" safe to act on, because there is no author _to_ act. A copied
  file has no such guarantor. A copied script can be edited in the consuming
  repository, and an edit made today is not overwritten until the next
  backfill or upgrade, which may never come. The property that made the
  generated discount honest — there is nothing to review, because there is
  nothing to author — does not hold for a copy, where the author simply has
  not edited yet.

- **Discount only bytes verified identical to the plugin reference.** The
  narrower version: count the bytes that differ from upstream, and discount
  the identical majority. This answers ADR-0008's objection in the case
  where the copy is genuinely unmodified, while still counting any local
  edit. Rejected because the discount has to be **re-evaluated per commit
  rather than declared once.** A file identical to upstream today may not be
  tomorrow — a single edit to one copied file removes the discount for that
  file while every sibling still qualifies — so the check that grants the
  discount must diff every copied file against the plugin reference on every
  commit. That diff is
  [slice 4](../specs/2026-08-01-distributable-guardrails-slice-4-audit-skill.md#an-existing-guardrails-from-an-older-plugin)'s
  drift comparison, which is specified and not yet implemented; declaring a
  discount that depends on a check that does not exist is a claim broader
  than the check behind it. And a discount keyed on "identical to upstream"
  trains the same habit
  [ADR-0005](0005-generated-files-discounted-from-change-size.md) names for
  routine overrides: once most copied files are exempt most of the time, the
  exemption stops being read.

## The measurement

**What was measured (2026-08-01), by `wc -l` and `wc -c` over the files
[slice 1's migration table](../specs/2026-08-01-distributable-guardrails-slice-1-foundations.md#the-migration-out-of-scripts-and-hooks)
moves into `.guardrails/`:**

| Portion                                    | Files  | Lines      | Bytes       | Counts toward change size?               |
| ------------------------------------------ | ------ | ---------- | ----------- | ---------------------------------------- |
| Tooling `.mjs` scripts (copied, `tooling`) | 33     | 8,596      | 355,756     | Yes — tooling counts                     |
| Test files (`hooks/test/**`)               | 14     | 6,546      | 283,344     | No — test lines are excluded at gate 4   |
| `README.md`                                | 1      | 71         | 10,165      | No — documentation is excluded at gate 4 |
| **Total copied corpus**                    | **48** | **15,213** | **649,265** |                                          |

The 33 tooling scripts are the 30 `scripts/*.mjs` files (excluding the two
`configure-*.mjs` files
[slice 1 carves out](../specs/2026-08-01-distributable-guardrails-slice-1-foundations.md#what-guardrails-is-and-what-therefore-stays-out-of-it-here))
plus `hooks/gate-1-edit.mjs`, `hooks/gate-4-task-completion.mjs` and
`hooks/lib/run.mjs`.

**Against the thresholds this repository enforces**
([thresholds.md](../standards/guardrails/thresholds.md)): change size warns
at 400 lines and errors at 800 lines. The 8,596 counted tooling lines alone
are roughly **10.7× the 800-line error threshold** (and ~21× the warn). A
discount that removed the copied tooling portion would drop that
contribution to zero; the present position leaves it counted and lets the
[change-size override register](../standards/guardrails/registers.md#the-change-size-override-register)
handle the result, which is
[fix 74](../standards/guardrails/cross-gate-rules.md#an-override-answers-a-push-back-it-is-not-a-fix)
working as designed.

**Not measured, and why.** How much a real consuming repository's branch is
inflated by copied bytes: `.guardrails/` does not exist yet. Slice 1 is
specified and unimplemented, and no consuming repository has received this
copy, so there is no real branch to measure. The 8,596 figure is the source
corpus at the current commit — the added-line ceiling of a fresh copy of
the tooling scripts alone, not a real bootstrap commit, which would also
carry generated files, documentation, wiring and the enforcement map. That
composite figure belongs to slice 3's measurement, and a consumer does not
yet exist to produce it. What would produce it: a bootstrap run against a
real consuming repository, its change size measured by gate 4 the same way
it resolves in production — not estimated from this source corpus.

This figure was captured once, on the date above. If this record moves
toward acceptance, re-capture it after the last commit that could change
the corpus, the same sequencing any quoted figure in this corpus requires.

## What would re-open this

A decision with no reversal condition is a decision nobody can revisit.
This position re-opens if
[slice 4](../specs/2026-08-01-distributable-guardrails-slice-4-audit-skill.md)'s
drift comparison becomes real and demonstrates, across actual consuming
repositories, two things at once: that copied files are in practice never
edited — the byte-identical property holds — and that the per-commit cost
of an "identical-to-upstream" discount is manageable. At that point
[ADR-0008](0008-tooling-complexity-band.md)'s premise — a copy _can_ be
edited, so the discount must be re-evaluated per commit — can be re-argued
against evidence rather than from the absence of it, and the narrower
rejected alternative above becomes the candidate rather than a speculation.
Until that check exists, a discount declared here is a claim no mechanism
enforces, which is the defect this corpus refuses.
